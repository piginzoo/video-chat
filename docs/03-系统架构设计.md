## 2. 架构决策记录（ADR）

### ADR-001 · UI 宿主：Chrome Side Panel API
- **背景**：需求要求右侧常驻侧边栏，视频切换时面板保持。
- **决策**：使用 `chrome.sidePanel` API（Chrome 114+，本机 156 ✓）。工具栏图标点击开/关面板（`sidePanel.setPanelBehavior({openPanelOnActionClick:true})`）；**标题栏右上角 ✕ 按钮调用 `window.close()` 关闭面板**（Side Panel 页面原生支持）。
- **替代方案**：content script 注入悬浮面板（侵入页面、易与站点样式冲突，否）；popup（点外部即关闭，无法跟随播放，否）。
- **后果**：面板为窗口级，跨 tab 共享 → 需自实现「跟随当前 tab」（ADR-008）。

### ADR-002 · 技术栈：原生 HTML/CSS/JS，零构建零依赖
- **决策**：不用 React/Vite/打包器。插件代码全部手写原生模块（ES Module）；LLM 回复渲染用**自制极简渲染器**（全量 HTML 转义 + `[mm:ss]` 链接化 + 缩进块→`<pre>`），不引入 markdown 库。
- **理由**：体量小（预估 ~2000 行）、加载零延迟、无供应链风险、prompt 已约束输出格式（纯文本+时间戳+tree 缩进），完整 markdown 渲染属过度设计。
- **后果**：如未来需要丰富 markdown，再引入 vendored 库（预留 render.js 单点替换）。

### ADR-003 · YouTube 字幕获取：多层降级（v1.0.1 依据实测修订）⚠️ 核心风险项
- **背景**：实测（证据 #7、#8、#9）推翻了原始三层假设：S1 匿名与页内凭据直拉**全部失效**；`ytInitialPlayerResponse` 全局变量不可靠。
- **修订后的实际架构**（按优先级）：
  1. **S2.5 官方文字记录面板刮取（全量主力，实测 ✅）**：nudge 开启 CC 后，程序化点击「显示文字记录」按钮，刮取面板全量 DOM 分段（60 行实测）。多语言选择器多路尝试规避 UI 文案差异。
  2. **S2 播放器拦截 + URL 重放（实测 ✅）**：`PerformanceObserver`（resource 事件）+ 钩入页面 `fetch`/`XHR` 捕获播放器自己的 timedtext 请求；**URL 原样重放**（签名参数一个都不能改——曾因追加 `fmt=json3` 导致签名失效，已修复），返回完整 json3。
  3. **S3 InnerTube player API**：`/youtubei/v1/player` 换取 captionTracks（实测接口可用），其 baseUrl 拉取在未登录态同样为空，保留给登录态场景。
  4. **终极兜底**：粘贴脚本（规格 §4.4）+ 用户开始播放时自动重试一次抓取。
  - **nudge 的关键实测结论**：播放器 PAUSED 时不拉字幕数据 → nudge 后若暂停则执行「静音快闪播放 2.5 秒后复原原时间点」触发加载（证据 #11）。
  - 依赖的播放器实时 API：`getOption('captions','tracklist')`（字段 `languageCode/displayName/kind`）、`getVideoData()`、`setOption('captions','track',…)`（证据 #10）。
- **跨世界协议教训（实现级）**：MAIN world（拦截器）与 ISOLATED world（桥接）之间用 CustomEvent 协议；但 content script 内部**不能用 `chrome.runtime.sendMessage` 调用同 tab 的其他 content script**（runtime 消息只路由到扩展页面，永不回到 content script——此 bug 曾让整条链路静默失效），必须同世界直调共享 API（`window.__VJX_BRIDGE_API__`）。
- **SPA 陷阱**：切视频后 `ytInitialPlayerResponse` 陈旧，videoId 一律以 URL 为准，轨道一律以播放器实时 API 为准。
- **编码后动作（已完成）**：S2/S2.5 真机实测通过（证据 #12、#13、#14），结果回填本文档。

### ADR-004 · B站字幕获取：官方 API 双轨制（v1.0.1 依据实测修订）
- **决策**：`view` API 取 cid（✅ 实测）→ `player/v2` 取 `subtitle.subtitles[]`（✅ 实测，无需 wbi 签名；**AI 轨道仅在登录态出现**，实测匿名全为空）→ **UP主 CC 轨道优先、AI 字幕其次** → 字幕正文拉取。
- **正文拉取的实测修订（关键）**：
  - `aisubtitle.hdslb.com`（AI 字幕正文）**页面直拉被 CORS 拒绝、扩展后台中转被 Tengine 403 防盗链**（缺 Referer）。
  - 解法：**declarativeNetRequest 规则**对 `aisubtitle.hdslb.com` 请求注入 `Referer: https://www.bilibili.com/` 并补写响应 CORS 头（`Access-Control-Allow-Origin/Credentials`），页面上下文直拉即可成功（✅ 实测：591 行 AI 字幕到手）。规则文件 `rules.json`。
  - 语言判断注意：AI 中文字幕的 `lan` 值为 `ai-zh`，中文判断必须用**包含 zh**（`/zh/i.test(lang)`）而非前缀匹配，否则会误触发英文翻译（实测踩坑已修复）。
  - 另发现播放器实际使用 `api.bilibili.com/x/v2/subtitle/web/view`（protobuf，裸 gzip）——本插件不需要走它，player/v2 JSON 路径足够。
- **风险与缓解**：登录态缺失 → 明确提示「登录后可获取 AI 字幕」+ 粘贴兜底（✅ 实测通过）。
- **真机验证（✅ 已完成，2026-11-05 登录态）**：AI 轨道视频（English AI 591 行 + 自动翻译、中文 AI 160 行不翻译）、跟随、总结（270 字/371 字带时间戳引用）全部通过。

### ADR-005 · 存储：chrome.storage.local + LRU 淘汰
- **决策**：全部持久化走 `chrome.storage.local`（规格 §5.2，不暴露 ✓）。Schema：
  ```
  settings:    { activeProvider, providers:{ deepseek:{apiKey,baseUrl,model},
                                            glm:{apiKey,baseUrl,model} } }
  transcripts: { [videoKey]: { site, videoId, p, title, lang, trackId,
                               rows:[{t,en,zh,tr}], fetchMode, status, updatedAt } }
  chat:        { [videoKey]: { messages:[{role,content,at}], updatedAt } }
  meta:        { schemaVersion }
  ```
  - `videoKey = site:videoId[:p]`（B站分P各自独立）。
  - **LRU 淘汰**：transcripts 超过 30 个视频（翻译缓存体积大头）按 `updatedAt` 淘汰；chat 保留最近 50 个视频。
  - 翻译缓存键：`videoKey + trackId`，即字幕轨道切换后重译（规格 §4.3）。
- **替代方案**：IndexedDB（容量更大但 v1 用不到，schema 复杂度不值）；storage.sync（会云同步，违背"不暴露"诉求，否）。

### ADR-006 · LLM 接入层：OpenAI 兼容协议 + Provider 抽象（v1.0.1 实测修订）
- **决策**：统一走 `POST {baseUrl}/chat/completions`（两家皆 OpenAI 兼容）。side panel 内直接 `fetch`（host_permissions 白名单 `api.deepseek.com/*`、`open.bigmodel.cn/*`，无 CORS 问题）。**SSE 流式解析**（`ReadableStream` 按行拆 `data:`，拼接 `delta.content`）。
- **推理模型适配（实测修订）**：`glm-5.3-flash` 为**始终思考模型**——API 错误 1210 明示「不支持关闭思考，仅支持 low/high/max」，且未知参数会被**静默忽略**（实测 `thinking:{type:"disabled"}`、`{enabled:false}`、`reasoning:{enabled:false}` 均无效）。最终方案：`thinking:{type:"low"}`；`reasoning_content` 以「💭 思考中…」可视化（不进正文与历史）；chat `max_tokens` 提高到 8000（**推理 token 计入输出上限**，曾出现推理烧尽 4000 上限导致正文为空）；流式增加 60 秒停滞检测 + 150 秒整体超时；空正文兜底报错。
- **Provider 抽象**：`providers.js` 暴露 `{id, defaultBaseUrl, defaultModel, baseUrlHint, transformPayload}` 注册表 → 未来加新服务商只需注册一项。
- **超时/重试**：连接超时 15s（翻译 90s）；流超时/停滞给出明确文案 + 手动重试。
- **错误分类**：401/403 → "Key 无效"；429 → "限流，稍后重试"；5xx/网络 → "网络或服务异常"。文案直接对应规格 §8。

### ADR-011 · AI 听录：无字幕视频的 ASR 兜底（v1.1，已实现并实测）
- **触发纪律**：只在「无字幕」卡片出现按钮；**有字幕的视频在代码路径上不可能触发**（按钮仅存在于 nosub 渲染分支），绝不浪费用户 ASR 费用。
- **B站音频获取（✅ 实测）**：`playurl?fnval=16` 的 `dash.audio[]`（最低 bandwidth）。**实测坑**：音轨常落在 PCDN 域 `mcdn.bilivideo.cn`（**.cn 不是 .com**），host_permissions 与 DNR 规则必须覆盖 .cn；offscreen 下载需 DNR 注入 Referer。
- **YouTube 音频获取（v1.1 实测修订）**：
  - ~~InnerTube `adaptiveFormats`~~：**实测 2026 年响应中音频条目已无 `url` 字段**（PO-Token/SABR 时代，ANDROID 客户端伪装亦被拦），音频直链方案全线不可用；
  - 播放器走 **SABR 合并流**（音视频混流，无独立音频请求，PerformanceObserver 亦捕获不到 `mime=audio` 分片）；
  - **最终方案：页面内实时捕获**——MAIN world `createMediaElementSource(<video>)` → `ScriptProcessor` 累积 PCM → 每 28 秒降采样 16k mono → 自编 WAV → 跨世界转发 sidepanel → 并发上传 `glm-asr-2512`。元素音频被捕获后自动旁路（用户看画面听不到声）。时间戳直接取 `video.currentTime`（精确，无插值误差）。代价：听录耗时 ≈ 视频时长（视频静音播放，用户可同步观看）；听录期间字幕自动重试被抑制，以听录结果为准。
- **glm-asr-2512 接口硬限制（实测文档）**：文件 ≤25MB、单次音频 ≤30 秒、仅 wav/mp3、**响应无时间戳**（仅整段文本）→ 块内按句切分、字符占比线性插值时间（YouTube 实时捕获用真实 currentTime，无此问题）。
- **语言探测**：转写文本 CJK 占比 >25% → `asr-zh`（不翻译）；否则 `asr-en`（自动进入 ADR-007 翻译管线转中文）。
- **限制**：>60 分钟视频暂不支持（一次性解码内存约束，B站路径）；纯音乐/无语音 → 明确报错。
- **实测（✅ 2026-11-05）**：
  - B站：22 分钟中文说话视频（1348s，0 轨道）：下载→解码→49 块→并发识别→**27 秒完成**，158 行，转写文本准确；缓存二次打开秒出零成本；约 0.25 元/次（0.0002 元/秒）；
  - YouTube：播放中视频实时捕获：28.14 秒/块、时间戳精确、英文歌词转写准确（GLM-ASR 返回 "I just died in your arms tonight..."）。
- **余额保护**：ASR 错误按 message 关键字映射（余额/欠费/balance）→「ASR 余额不足：请到智谱开放平台充值（按量计费部分）」；ASR 配置独立于 LLM 配置（设置页独立 section，含连通性测试）。

### ADR-007 · 批量翻译流水线（双语对照的引擎）
- **决策**：字幕加载完成后自动启动（非中文脚本，规格 §4.3）：
  1. 按行切块：每块 ≤40 行且 ≤3500 字符；
  2. prompt 契约：逐行翻译、保持行数、不合并不解释，输出 JSON 行数组（`{"i":行号,"zh":"译文"}`），解析失败单块重试 1 次；
  3. **并发 2** 块并行，UI 进度条实时更新，译文逐块落 storage（断点续翻：重开视频从未完成块继续，规格 §8）；
  4. 全部完成 → 标记缓存生效（「二次打开秒出」）。
- **费用量级**：1 小时视频 ≈ 1.5 万 token 输入 + 1 万输出，GLM flash 档近乎免费，DeepSeek 约几分钱（规格 §7.3）。
- **替代方案**：播放时逐句实时翻（每句一请求，延迟+限流，已否决——访谈确认）；整篇一次请求（超长必截断，否）。

### ADR-008 · 跟随引擎：进度上报 + 双向命令通道
- **决策**：
  - **进度上行**：content script 监听 `<video>` `timeupdate`（约 4Hz，节流至 250ms）→ `runtime.sendMessage` 推给 side panel；side panel 另设 1s 轮询兜底（面板刚打开时补状态）。
  - **命令下行**：side panel `chrome.tabs.sendMessage(tabId,{cmd:'seek',t})` → content script 设 `video.currentTime`。点击字幕行、点击聊天时间戳、快捷指令同一条通道。
  - **当前行计算**：side panel 持有 rows 数组二分查找 `t` 所在行 → 高亮 + `scrollIntoView` smooth；手动滚动即暂停跟随 3s（原型交互，规格 §4.2）。
  - **SPA 路由监听**：YouTube 监听 `yt-navigate-finish` 事件；B站用 `MutationObserver` 观察 URL 变化（含切P）。videoId 变化 → side panel 切换数据源（规格 §3 自动跟随）。
  - **tab 激活监听**：`chrome.tabs.onActivated` / `onUpdated` → 面板刷新为当前 tab 的视频。
- **时钟漂移**：进度以 content script 上报为准，面板不做本地计时。

### ADR-009 · 时间戳引用协议（模型 ↔ 界面契约）
- **决策**：system prompt 强约束三件事：① 以中文回答；② 引用脚本内容时必须标注 `[m:ss]` 且**只允许使用所给脚本中真实存在的时间**；③ 上下文提供脚本时带每行时间戳标记。渲染层正则 `\[(\d{1,2}):(\d{2})\]` → 可点击链接 → 走 ADR-008 seek 通道。
- **防幻觉**：prompt 附带"无对应内容的时间戳禁止编造"；时间戳 seek 后若行内容不符由用户自然发现，v1 不做反向校验。

### ADR-010 · 安全与隐私
- **决策**：
  - API Key 仅存 `chrome.storage.local`；UI 掩码显示、可切换明文；**不写入任何源码/文档/日志**（本次测试 Key 存于仓库外 `.test-secrets.local.json`，测试后删除并由用户吊销）；
  - 脚本/对话仅发送至用户配置的 LLM 端点（DeepSeek/Glow 官方或其自定义中转），无遥测无采集；
  - MV3 CSP 默认禁止远程代码，插件不加载任何远程脚本；渲染层**全量 HTML 转义**（防站点内容/模型输出注入 XSS）；
  - `host_permissions` 最小化：youtube/bilibili（含 hdslb 字幕域）+ 两家 LLM 域。
